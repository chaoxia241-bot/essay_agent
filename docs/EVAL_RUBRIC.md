# 评测体系设计（P1.5 起实施）

> 来源：改造自参考项目 `数据处理/大模型评分标准-提示词版.txt`（五维 1–5 分 rubric，含"溯源性"维度）+ `evaluation/ragas_eval` 经验。
> 参考项目的"安全性"维度对论文场景无意义，替换为**引用正确性**。

## 1. 离线评测集规范

- 规模：P1 起步 30 条，P2 扩到 80 条，P5 扩到 150 条。
- **必须用中文 query**（与真实使用一致），每条标注：

```json
{
  "query_id": "q001",
  "query": "MOSI 数据集上，哪些方法的 Acc-2 超过了 85%？",
  "type": "factual | relational | research",
  "gold_evidence_ids": ["ev:xxx", "ev:yyy"],
  "gold_answer_points": ["方法 A 达到 86.2%", "方法 B 达到 85.4%"],
  "difficulty": "easy | medium | hard"
}
```

- `type` 分布：factual 40% / relational 35% / research 25%（对应三档路由）。
- 覆盖跨语言难点：中文 query 查英文表格、术语混写（"用 LoRA 做 MSA 的论文有哪些"）。

## 2. 检索层指标（自动）

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| Recall@10 | gold evidence 被召回的比例 | P1 建立基线，逐轮提升 |
| Evidence Recall | 至少命中一条 gold evidence 的 query 占比 | ≥ 85% |
| MRR | 首条命中证据的平均排名倒数 | ≥ 0.6 |
| 跨语言 Recall 差 | 中文 query vs 英文改写 query 的 Recall@10 差值 | 越小越好，>15% 说明跨语言策略失效 |

最后一项是本项目特有指标 —— 直接检验 ADR-008 的三路召回是否奏效。

## 3. 生成层 Rubric（LLM-as-Judge，1–5 分）

### 3.1 相关性（Relevance）

- 5：完全聚焦问题，无冗余
- 4：紧扣问题，含少量非必要背景
- 3：触及主题但未精准回应，需追问
- 2：严重偏离
- 1：答非所问

### 3.2 正确性（Accuracy）

- 5：所有数值、方法名、数据集名与原文完全一致
- 4：个别非关键细节轻微不精确
- 3：混入错误信息，可能误导
- 2：明显事实错误
- 1：完全错误或数值张冠李戴

### 3.3 完整性（Completeness）

- 5：覆盖所有主要与次要方面
- 4：覆盖核心信息点，次要信息略有欠缺
- 3：明显信息缺口
- 2：遗漏大部分核心信息
- 1：几乎无有效信息

### 3.4 证据可追溯性（Groundedness）—— 本项目核心维度

- 5：每条结论都带可定位引用（Paper + Page/Section/Table），内容与原文完全一致
- 4：结论均可溯源，但个别引用粒度偏粗（只到论文级）
- 3：部分结论有引用，部分无出处
- 2：看似合理但无法在原文找到支撑
- 1：与原文冲突或伪造引用

### 3.5 引用正确性（Citation Correctness）—— 替换参考项目的"安全性"

- 5：引用全部指向正确证据，且支撑对应结论
- 4：引用正确，个别指向的证据不够直接
- 3：存在引用错位（结论对但指向了别处）
- 2：多数引用无法支撑结论
- 1：引用不存在（幻觉 ID）或张冠李戴

### 3.6 冲突识别（P5 起启用）

- 5：主动识别并说明条件差异导致的表面冲突
- 3：识别出冲突但未比较实验条件
- 1：忽略冲突，直接给出"X 优于 Y"的全局结论

## 4. Agent 层指标（P4/P5 起）

- 路由准确率（三档）
- 工具选择准确率
- 子问题覆盖率（Planner 产出的子问题是否覆盖研究问题各个方面）
- 任务完成率
- token 消耗 / 单次研究成本
- checkpoint 大小（验证 State 只存 ID 的约束是否守住）

## 5. 评测实施

- Judge 模型：与生产模型分离（用更强的模型评判，避免自评 inflate）。
- 每条 query 评 3 次取平均（LLM 评分有波动）。
- 结果落 `data/eval/`，每轮保留，形成趋势曲线。
- **评测一律在 GPU 环境（gpu_8g profile）跑**（ADR-010）。

## 6. 与 P7 的衔接

评分 ≤3 分的样本自动进入失败样本池，按失败类型分类：

```text
相关性/改写失败 → Query Rewrite SFT 数据
引用错误      → Evidence preference 数据（DPO）
子问题覆盖不足 → Research trajectory 数据
路由错误      → 路由分类数据
```

这正是文档 §12「根据失败类型选择训练方式」的落地路径。
